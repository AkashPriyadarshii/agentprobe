Docs / v0.0.2

Every flag, check and score rule.

agentprobe fetches a page the way an autonomous client does, then scores what it found across five pillars. The CLI, the GitHub Action and the hosted audit all call the same five engines, so a score means the same thing wherever you read it.

Install

Node 18 or newer. Nothing else to configure.

$ npx @akashpriyadarshii/agentprobe https://example.com

# or install it for repeated runs
$ npm install -D @akashpriyadarshii/agentprobe
$ npx agentprobe https://example.com

Pin a version in CI so a scorer change cannot fail a green build without a commit. The package ships ESM and CommonJS builds plus TypeScript types.

Run

A target is either a public URL or a directory on disk. A URL is fetched over the network; a directory is read as a built static export, which is the mode that matches what a crawler receives after deployment.

$ agentprobe https://example.com
$ agentprobe ./dist
$ agentprobe https://preview.example.com --min-score 90

Default output is the terminal report: score, grade, the five pillars and a fix list. Each failing check prints the reason it failed and the change that clears it.

Exit codes are the CI contract.

Exit codes
CodeMeaning
0Score at or above the threshold.
1Score below the threshold. The job fails.
2Invalid target, unreachable host, or a parse error.

Score

Five pillars, twenty points each, one hundred total. Every check carries a weight. A pass keeps the full weight, a warning keeps half, a failure keeps nothing.

Nothing in the scorer is random, and no check depends on another. The same build returns the same score, which is what makes a threshold usable as a gate.

Pillars

Crawler access, 3 checks

Reads /robots.txt and evaluates it against 15 production AI user agents, including GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot, Bytespider, Amazonbot and Applebot-Extended. A disallow rule aimed at a group that covers those agents fails the check. A missing robots.txt is a warning rather than a failure, because the default behavior is to allow.

LLM manifest, 4 checks

Checks for /llms.txt and /llms-full.txt, then reads what is inside: an H1, a summary line, sections with links, and a size that stays inside a token budget. A manifest that exists but contains a marketing page costs you the spec-compliance points.

Structured context, 4 checks

Parses the HTML for semantic landmarks (main, nav, header, footer), a single H1 with a heading hierarchy under it, a usable <title> and meta description, and Schema.org JSON-LD that names the entity and the page type.

Actionability, 4 checks

Measures whether the fetched document is usable without a browser: server-rendered content in the initial HTML, a Markdown alternative through content negotiation, accessible names on interactive controls, and form fields with labels. A client-rendered page that ships an empty root element fails here, and that failure is usually the largest single deduction.

Protocol discovery, 4 checks

Looks for /.well-known/ai-catalog.json (Agentic Resource Discovery), /.well-known/mcp.json (Model Context Protocol server declaration), a skills index, and x402 payment headers for paid endpoints. These are early standards, so a missing manifest is a warning, not a failure.

JSON output is the stable interface. Its shape is the AuditReport type exported from the package, so a dashboard can consume it without parsing the terminal layout.

CI

The action runs after a deploy, audits the preview URL and fails the job when the score drops under the threshold. Keep fail-on-error false for previews that may sit behind a WAF, true for production.

name: agent readiness
on: [push, pull_request]

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: AkashPriyadarshii/agentprobe@v1
        with:
          target: https://preview.your-site.com
          min-score: 80

Without the action, run the CLI directly and let the exit code fail the step:

$ npx @akashpriyadarshii/agentprobe ./dist --min-score 85

For a readable job summary, add --summary >> "$GITHUB_STEP_SUMMARY" to the same step.

Library

The engines are exported individually, so a build step can run one pillar without fetching the rest.

import { auditTarget } from '@akashpriyadarshii/agentprobe';

const report = await auditTarget('https://example.com', { minScore: 80 });

console.log(report.summary.totalScore, report.summary.grade);
for (const pillar of report.pillars) {
  for (const check of pillar.checks) {
    if (check.status !== 'pass') console.log(pillar.name, check.name, check.recommendation);
  }
}

Single-pillar functions: auditCrawlerAccess, auditLLMsTxt, auditSemanticStructure, auditActionability, auditProtocolDiscovery. Report formatters: formatTerminalReport, formatJsonReport, formatPlainReport, formatGitHubStepSummary.

Scaffold

init writes a starting llms.txt and a permissive robots.txt so the two cheapest checks pass immediately. It never overwrites an existing file. If a public/ directory exists it writes there, otherwise to the current directory.

$ npx @akashpriyadarshii/agentprobe init --name "Acme" --description "Static site for Acme."

created  /site/public/llms.txt
created  /site/public/robots.txt

Both files are starting points, not finished manifests. Replace the placeholder links with real ones, or the spec-compliance check will still dock points.

Limits

No JavaScript execution. The scorer reads server HTML. A client-rendered page with an empty document fails the actionability checks because that is exactly what an agent without a browser receives.

No private targets. The hosted endpoint refuses localhost, private ranges and .internal hosts. Run the CLI locally for anything that is not public.

No stored reports. The hosted audit fetches, scores and returns. There is no account and no database. Responses are cached at the edge for five minutes.

No guessing behind a WAF. When a strict WAF blocks the server-side fetch, the audit reports the error instead of inventing a score.
