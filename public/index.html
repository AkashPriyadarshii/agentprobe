Method
100 points

Five checks, twenty points each.

Every check carries a weight. A failure deducts the full weight, a warning deducts half, and each deduction carries the fix that clears it. Nothing in the scorer is random, so the same build returns the same score.

Crawler access robots.txt rules for 15 AI user agents, plus the sitemap declaration. 3 checks
LLM manifest llms.txt and llms-full.txt against the spec: H1, summary, sections, token budget. 4 checks
Structured context JSON-LD, main and nav landmarks, one H1, ordered headings, description. 4 checks
Actionability Markdown negotiation, accessible names on controls, content present before hydration. 4 checks
Protocol discovery ai-catalog.json, mcp.json, a skills index, x402 payment headers. 4 checks

Grades: 95+ A+ / 85 A / 75 B / 60 C / 40 D / below 40 F

Limits

What it does not do.

No JavaScript
The scorer reads server HTML. A client-rendered page with an empty document fails the actionability checks, because an agent that does not run JavaScript sees the same empty document.
No private targets
The hosted endpoint refuses localhost, private ranges and .internal hosts. Run agentprobe ./dist for anything that is not public yet.
No stored reports
The endpoint fetches, scores and returns. There is no account and no database. Responses are cached at the edge for five minutes.
No guesswork
A strict WAF can block a server-side fetch. When that happens the audit reports the error instead of inventing a score.
